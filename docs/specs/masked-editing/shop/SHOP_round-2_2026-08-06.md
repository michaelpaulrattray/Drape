## Two instrument defects, both found before any verdict rested on them

### 1. The mask was being read from the wrong channel (D-210's class, again)

**SAM 3 answers with an RGBA cut-out: the segmentation is the ALPHA channel, and
RGB carries picture content.** The reader converted the response to greyscale and
measured that — so the first run measured *the darkness of the subject's hair*
and called it a mask.

The tell was `fully-opaque 0.00%` on every SAM 3 row. Proven, not inferred: the
alpha channel's non-zero count and its fully-opaque count are **identical**
(3.69% and 3.69%), so the real mask is perfectly binary.

`.toColourspace("b-w")` cannot catch this, because it *converts* four channels to
one — so the single-channel guard it was paired with could never fire. A check
whose passing state required it to have read nothing is not a check.

Corrected figures for SAM 3, all previously understated:

| region | as first measured (wrong) | actual |
|---|---|---|
| eyeglasses | 0.50% | **1.37%** |
| hair | 0.51% | **3.69%** |
| face skin | 2.82% | **4.97%** |
| softness | "1.4–5.0% soft" | **0.0% — entirely binary** |

**Round one is not affected.** EVF-SAM returns a genuine single-channel greyscale
mask, so the old reader was correct *for that model*; re-measured here, its
numbers reproduce (negative control 0.087% then, 0.09% now). D-213's finding and
the rejection both stand on their original evidence.

### 2. "Softness" had no floor (D-203's class)

The first metric counted any byte strictly between 0 and 255 as soft. BiRefNet's
matte *interior* sits at 250–254, so the solid middle of a subject scored as
edge, and the endpoint read "46% soft" when its actual ramp is a hairline. Round
one's ratified **"61% soft"** for the same endpoint carries the same defect: the
verdict (it IS a true matte) survives; **the number that justified it does not.**

Replaced with a genuine ramp measure — the share of a mask's own extent carrying
intermediate values (26–229) — and given both controls before use:

| control | expectation | measured |
|---|---|---|
| FLOOR — SAM 3's provably binary region | ~0% | **0.0%** |
| CEILING — the same region through the real `featherMask(r=6)` | clearly non-zero | **32.4%** |

The script throws rather than reporting if either control fails.

### 3. A third D-210 instance, in the preview renderer

`sharp` **promotes a raw single-channel buffer to three channels through
`.resize()`** (proven: `channels=3`, 405000 bytes for a 300×450 result). Reading
it one byte per pixel walks the first third of an RGB-interleaved buffer and
draws a striped wedge that looks like a mask if you are not paying attention. It
was caught because six panels that must differ looked identical. The renderer now
forces the colourspace back and **asserts the stride**.

Three instances of this one class in a single session. It is silent every time.

## The hair row: neither model fills it, the composition does

SAM 3 knows *where* the hair is and has no edge. BiRefNet knows *how soft* the
edge is and cannot tell hair from shoulder. D-212's rider forbids binary outlines
on soft boundaries, so the honest test was whether the intersection is what
neither is alone.

| mask | coverage | ramp/extent |
|---|---|---|
| SAM 3 hair region | 3.69% | 0.0% |
| BiRefNet Matting subject | 53.05% | 2.7% |
| `min(region, matte)` | 3.30% | **15.0%** |
| `min(dilate(region, 4), matte)` | 3.67% | **17.4%** |
| `min(dilate(region, 8), matte)` | 3.96% | 15.9% |
| `min(dilate(region, 16), matte)` | 4.48% | 13.8% |

**It composes.** A 0%-ramp cut-out becomes a 17% -ramp matte, and the strip
(`output/masked/hair-composition/COMPOSITION-strip.jpg`) shows the flyaway wisps
surviving. The small dilation matters because SAM 3's hard boundary otherwise
sits *inside* the matte's flyaway zone and `min` clips the very wisps the matte
was brought in for — growth lets the matte decide where the hair ends.

**r=16 visibly bleeds onto the forehead**, which is D-211's face-carve-out law
earning itself on a picture rather than in the abstract. r≈4 is the working value
and is **provisional** — one specimen, and it wants the other 23 faces before it
is a constant.

`maskGeometry` has union (`max`) and subtract (`min(a, 255-b)`) but **no
intersection**. `intersectMask` = `min(a, b)` is the operation this row needs. It
was computed inline in the probe rather than added, because product code is not
being touched before the founder's face wall.

### Still unfilled, and one of them may stay that way

- **There is no dedicated face-parsing model in fal's catalogue.** The keyword
  search returns zero rows. This is a finding, not a gap in the search: the
  face-parsing row is filled by a text-promptable segmenter or not at all, and
  SAM 3 is doing that job creditably at 0.77–0.96 confidence on named regions.
- **No hair-specific matting model exists either.** The composition above is the
  answer, and it is better than a single model would be because each half is
  independently checkable.
- ~~**SAM 3 returns frames and lens interiors as ONE region.**~~ **SOLVED, D-217**
  — the split can be *asked for*: a second prompt for `eyeglass lenses`, then
  `frames = union − lenses`. Holds on both frame weights, lenses sit 100% inside
  the union, the eye sits inside the lens region, and the frame areas track the
  physical glasses (0.36% thick rims vs 0.14% fine wire on identical unions). No
  derived hole-fill needed. `scripts/calibration/glasses-frame-lens-split.mts`.
- **SAM 3 vs SAM 3.1 are indistinguishable** on every region measured (within
  0.02% coverage, ±0.01 score). No reason to prefer either yet; SAM 3.1 was
  slower on two rows.

## What is not claimed

No routing row is ratified here. Nothing has been composited, no edit has been
rendered, and no seam has been scored — this round establishes only that masks of
the right shape can be obtained, and with which controls. The bake-off (NBP vs
GPT Image 2) and the seam work belong to the glasses fixture.
